AER-149 — a web server that only hands out files

01

What It Is

Once the web server did everything. Job by job it moved to Connect. After this epic, nothing is left on the web server.

Aeons ago

One server. The client talks to Tomcat for all of it, calculations included.

Years ago

Connect arrives and takes the calculations. Context, system info and RPC calls still come from Tomcat.

Today

Context and system info moved to Connect. The web server still reads the database, picks the language and the customer, and writes settings into the page.

After AER-149

The web server hands out files and nothing else. What the client shows and does comes from Connect alone.

The road in between: system info to Connect, the context to Connect, GWT-RPC and the servlets removed, client errors reported to Connect.

03

What It Enables

what we get for sure A very simple, very dumb web server. No Tomcat, no Java, no database connection, no state. Nothing to patch, nothing to crash.
optional Serve it from Amplify Or a bucket, a CDN, plain nginx. A deploy is uploading files.
optional Swap one side, keep the other New Connect under the same client. New client on the same Connect.
optional The client in its own repo Nothing on the serving side ties it to this repo any more.
optional A new client, next to the old one It only needs to speak the Connect API. No big bang.

We don't have to do any of it.
Today we can't. After AER-149 we can.
